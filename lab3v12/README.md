# Лабораторна робота №3 — варіант 12

**Тема:** життєвий цикл об'єкта та керування ресурсами.
**Клас:** `BluetoothConnection`.
**Автор:** Богдан Ковенько.

Це навчальна імітація Bluetooth-з'єднання. Bluetooth-адаптер і реальний
пристрій не потрібні. Поле `_isPaired` позначає стан імітованого ресурсу.

## Що містить проєкт

- `Program.cs` — клас `BluetoothConnection` і метод `Main` із трьома сценаріями.
- `lab3v12.csproj` — файл консольного проєкту .NET 8.
- `console-output.txt` — фактичний результат запуску програми.
- `.gitignore` — виключає тимчасові папки збірки з Git.

## Запуск на Windows

1. Розпакуй архів. Перенеси папку `lab3v12` у свій наявний `OOP-Kovenko`.
2. Відкрий командний рядок **CMD**.
3. Якщо репозиторій розташований за твоїм попереднім шляхом, виконай:

```bat
cd /d "%USERPROFILE%\OneDrive\Desktop\OOP-Kovenko"
dir lab3v12\lab3v12.csproj
dotnet run --project lab3v12\lab3v12.csproj
```

Якщо папка розташована в іншому місці, підстав її фактичний шлях у `cd /d`.
Команда `dir` повинна показати файл `lab3v12.csproj`. Помилка
`Couldn't find a project to run` означає, що команда виконана не в тій
папці або шлях до `.csproj` неправильний.

Потрібен .NET SDK 8 або новіший. У проєкті дозволено запуск на новішій
основній версії .NET, якщо середовища виконання .NET 8 немає. Новіший SDK
під час першої збірки може завантажити пакети для цільової версії .NET 8.

### Якщо створюєш проєкт самостійно

У кореневій папці `OOP-Kovenko` виконай:

```bat
dotnet new console -o lab3v12
```

Повністю заміни створений `Program.cs` кодом із комплекту і запусти:

```bat
dotnet run --project lab3v12
```

У цьому випадку файл `.csproj` створить твій SDK для своєї версії .NET.
Цей спосіб використовуй лише тоді, коли папки `lab3v12` ще немає.

## Три сценарії

| Сценарій | Коли закривається з'єднання | Шлях виклику |
| --- | --- | --- |
| `using` | Під час виходу з блоку, зокрема через виняток | `Dispose()` → `Dispose(true)` |
| Явний виклик | У місці виклику `Dispose()`; у прикладі це блок `finally` | `Dispose()` → `Dispose(true)` |
| Без `Dispose()` | Під час фіналізації недосяжного об'єкта | `~BluetoothConnection()` → `Dispose(false)` |

`GC.SuppressFinalize(this)` скасовує фіналізацію вже звільненого об'єкта.
`_disposed` робить повторний `Dispose()` безпечним.
`TransferData()` після звільнення ресурсу викидає `ObjectDisposedException`.

Клас не має власних керованих ресурсів з `IDisposable`, тому в гілці
`if (disposing)` залишено пояснення і діагностичний вивід. Пам'ять для
рядка, масивів та самого об'єкта звільняє GC, а не `Dispose()`.

Третій об'єкт створено в окремому методі з `NoInlining`. Після повернення
з методу локальне посилання більше не утримує об'єкт. `GC.Collect()`
ініціює збирання, `GC.WaitForPendingFinalizers()` очікує виконання
фіналізаторів, а другий `GC.Collect()` дозволяє прибрати вже фіналізовані
об'єкти. Примусовий GC і вивід із фіналізатора використані для демонстрації.
У звичайній програмі час фіналізації не визначений, а під час завершення
процесу фіналізатор може не виконатися.
